# Loops and gaps found in the v1.0 statement, and how the build resolves them

The v1.0 statement (docs/SPEC.md) already closed the 30 issues from the earlier review. Building it surfaced a second, smaller set. Each item below is a place where two rules fight each other, or a promise with no mechanism. The resolution column is what the code does.

| # | Loop or gap | Where | Resolution in the build |
|---|---|---|---|
| 31 | "Only for this resume" skills vs "master profile is the single source of truth". A skill that is not saved to the profile has no home, so traceability (every line traces to a profile entry) would fail for it. | SPEC 7 step 3, 15.5 | The session carries an explicit overlay (`session.overlay.skills`). Traceability resolves a source in the profile OR the overlay of the same session. The snapshot stores the overlay, so a saved resume stays explainable even if the profile changes later. |
| 32 | "Have this, AI-assisted" is a level in 6.3 but the step-3 mini-form asks for level AND an AI-assisted yes/no, which allows "Some exposure + AI-assisted", a combination with no printed wording. | SPEC 6.3 vs 7 step 3 | Levels are exactly four: have, have_ai, exposure, none. The AI-assisted toggle only applies to "Have this" and simply switches have to have_ai. Exposure never carries an AI label. |
| 33 | Interpersonal skills need an example, and "Have this" already needs "Where I used it". Two notes for one skill. | SPEC 6.3 | One private note serves both. "Where I used it" is required for every have/have_ai skill, interpersonal or not. |
| 34 | "Unconfirmed numbers are stripped" (9, enforcement) vs "the engine never changes the student's text" (11). Stripping a number silently rewrites a bullet. | SPEC 9 vs 11 | The engine never edits text. An unconfirmed number raises a blocking integrity violation on that line; the student either confirms it ("I can explain how I got this number" plus a private note) or edits the bullet. Approval is blocked until resolved. |
| 35 | Trim order puts About Me last, but Content and Writing puts About Me first in the layout. Trimming the lead section of a writing resume last is fine, but the spec never says trims are reversible. | SPEC 10 vs 13.1 | Trims are applied to a copy of the model in order and listed in the preview. Changing the template or selection rebuilds from scratch, so no trim is permanent. |
| 36 | Education prominence has three sources of truth: the family table, the "posting mentions a degree" rule, and the General family. Order of precedence is unstated. | SPEC 10 | Precedence: posting mention > family mode. A mention upgrades compact or normal to prominent; it never downgrades. |
| 37 | "GitHub shown for Software and Web" plus "posting override" plus "manual override" with no precedence. | SPEC 6.5 | Precedence: manual override (true/false) > posting request (true) > family default. Null manual override means "rule decides". |
| 38 | The approval snapshot is defined, but what counts as "a change" was not. Toggling a link, confirming a number and editing a bullet all change output. | SPEC 7 step 6 | The approval hash covers the full resume model plus template id plus page size. Any rebuild that yields a different hash clears approval. |
| 39 | "Store locally by default" plus Supabase sync: the photo is device-only but a naive sync would upload it inside the profile JSON. | SPEC 6.1, 17 | Sync strips `basics.photoDataUrl` before upload and never sends it to any edge function. |
| 40 | Company check needs a web source but the statement does not name one, and most "registries" need keys. | SPEC 8 | Best effort: a public company-name listing (Clearbit autocomplete, no key) plus a check whether `<slug>.com` or `<slug>.in` responds. The note states exactly that and nothing more. Offline or empty config gives "Not checked". |
| 41 | Rules-only extraction cannot know Must vs Nice unless the posting has headings. The private summary would show "unknown" priorities. | SPEC 7 step 2 | Priority has three values: must, nice, unknown. The review screen lets the student toggle it. Unknown is treated as nice for ordering and as a plain requirement in the summary. |
| 42 | The 10-minute target depends on the JD link working, but link fetching is "best effort". | SPEC 19, 27 | Pasting text is the primary path in the UI copy; the link is an accelerator. A failed fetch costs one screen, not the session. |
| 43 | "Programming" is a Skills sub-group, but the catalogue prefill mixes "AI tools" (a tool) with named tools the student adds. "AI tools" as a skill name would be meaningless on a resume. | SPEC 6.3 | "AI tools" is not a printable skill. The student adds named tools (ChatGPT, Midjourney) as custom tool skills, and the have_ai level covers skills practised with AI help. |
| 44 | Two-column templates must keep "logical reading order", but a sidebar-first DOM reads skills before the name. | SPEC 13.1 | DOM order is always header, main content, sidebar. CSS grid moves the sidebar visually. The PDF text layer therefore reads in the logical order. |
| 45 | The spec says the PDF is generated by the tool, but a serverless edge function has no browser to lay out HTML. | SPEC 13.1 | v1 uses the browser's own print-to-PDF of the approved snapshot (true text layer, embedded fonts, no raster). Approval still gates it: the print dialog only opens after approval and the snapshot is saved first. A server-side PDF (pdf-lib) is a planned upgrade, not required for integrity. |

Nothing here changes the integrity rules. Every resolution either picks a precedence the statement left open or replaces a silent rewrite with a visible block.
